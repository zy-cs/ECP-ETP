# 评标系统会话保活脚本（keepalive）

面向国网黑龙江辅助评标系统的 Tampermonkey 用户脚本：在长时间停留于系统页面时，按固定间隔发送一次**只读**心跳请求，维持当前登录会话不被超时踢出；同时把运行状态和掉线原因记录在页面上，方便自查。

> 本项目为个人辅助工具，仅作用于本人已登录、已获授权的系统会话。不含自动登录、凭据伪造、越权访问或任何业务数据写入。

---

## 它做什么

- 每 N 分钟（默认 2 分钟）向上级服务端发送一次只读查询请求，携带你当前已登录的会话凭据，让服务端判定会话仍在活跃。
- 右下角常驻一条状态条，实时显示：是否运行中、最近一次心跳的 HTTP 状态与耗时、连续成功次数、异常信息。点击可展开最近日志。
- 检测会话是否已失效（凭据被清除 / 服务端返回未授权），并记录失效时的页面卸载标记，用于区分「自己点关闭」「页面刷新」「服务端到期」三种掉线原因。
- 提供一键诊断日志导出，便于反馈问题。

## 它不做什么

- 不刷新页面、不打开新窗口、不模拟点击。
- 不拦截、不阻止系统原有的登出流程。
- 不读取、不修改、不延长凭据本身的有效期。
- 不改动任何业务数据，请求的是只读接口。
- 不在未登录状态下做任何动作；没有凭据时只等待并提示。

---

## 安装

1. 浏览器安装 Tampermonkey。
2. 在 Tampermonkey 管理面板新建脚本，把 `keepalive-v3.user.js` 全文粘贴进编辑器保存；或直接把 `.user.js` 文件拖进浏览器窗口，在安装页点「安装」。
3. 首次安装时 Tampermonkey 会请求跨域请求、脚本存储、剪贴板等权限，需允许，否则心跳发送不出去。
4. 浏览器需开启开发者模式，Tampermonkey设置允许用户脚本
5. 打开评标系统页面并刷新，右下角出现状态条即生效。

> 本脚本运行在内网环境，不通过公网仓库分发，因此**没有自动更新**。升级方式是拿到新版文件后覆盖现有脚本内容，再刷新页面。版本号写在脚本头部与状态条里，升级后可直接核对。

## 使用

右下角状态条

| 显示内容                                 | 含义                  |
| ------------------------------------ | ------------------- |
| 保活 v3 运行中 / 已暂停                      | 当前开关状态与心跳间隔         |
| 心跳 HTTP 200 code=200 · 时间 · 连续成功 N 次 | 最近一次心跳结果正常          |
| 心跳 HTTP 401 / code=401               | 会话已失效，需要重新登录        |
| 未登录 · 等待登录                           | 当前页面还没有登录凭据，登录后自动开始 |
| 异常：…                                 | 网络错误、网关拒绝等，附状态码与片段  |

点击状态条可展开或收起日志（保留最近若干条，倒序显示）。

脚本菜单（Tampermonkey 图标上的本脚本菜单）

| 菜单项           | 作用                         |
| ------------- | -------------------------- |
| 开启 / 暂停保活     | 立即切换，设置会保留                 |
| 立刻发送一次心跳      | 手动触发一次，用于验证连通性             |
| 设置心跳间隔（分钟）    | 允许 1–60，建议 2–5。间隔过短会增加无效请求 |
| 复制诊断日志（发给我排查） | 把状态、计数、掉线原因、最近日志复制到剪贴板     |
| 清除日志          | 清空本地记录                     |

---

## 状态与掉线原因

| 状态         | 含义          | 处理                                    |
| ---------- | ----------- | ------------------------------------- |
| ok         | 心跳成功，会话正常   | 无需处理                                  |
| error      | 请求失败（非 401） | 看状态条上的状态码；403 通常是网关校验，脚本会自动改用扩展通道重试一次 |
| expired    | 服务端返回 401   | 会话已到期，重新登录                            |
| no_token   | 当前页面没有登录凭据  | 登录后自动开始，无需操作                          |
| logged_out | 检测到凭据被清除    | 展开日志看记录的卸载标记，判断是主动关闭、页面刷新还是被服务端登出     |

掉线取证的价值在于：如果是服务端判定会话到期而前端被动登出，日志里不会有「关闭」「刷新」标记；如果是自己关页面或被刷新，则能看到对应标记。这能区分「保活没起作用」和「本来就是自己关的」。

## 常见问题

**状态条显示运行中，但过一段时间还是被登出**  
先看日志里最后一次成功的记录时间。若最后一次成功就在登出前不久，说明心跳本身正常，是服务端另有会话策略（如绝对有效期、单点登录冲突）；若连续失败，看状态码定位网络或网关问题。

**心跳一直是 403**  
网关要求携带来源页面信息，脚本已在页面直连失败时自动改用扩展通道并补上来源信息。若仍 403，可能是网关策略变更，用诊断日志反馈。

**状态条不见了**  
页面刷新后脚本会在页面加载完成时重建状态条。若完全没有，检查脚本是否处于启用状态、目标地址是否在匹配范围内。

**换了一台机器或换了账号**  
脚本只使用当前页面已登录的凭据，不保存凭据本身。换机后重新登录即可，状态和日志是本地的，不会跟随。

---

## 合规与边界

- 本脚本只对本人拥有访问权限的系统、在本人已登录的会话内工作，不适用于他人账号或未授权环境。
- 心跳请求复用现有会话，属于维持在线状态，不构成身份伪造或权限提升。
- 使用前请确认符合所在单位的信息系统使用与安全管理规定；如单位明确禁止此类客户端辅助脚本，请勿使用。
- 脚本内部涉及的系统地址与接口细节应视为内部信息，不应公开传播或提交到公开仓库。
